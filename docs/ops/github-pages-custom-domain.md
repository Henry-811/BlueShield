## Cutover checklist

1. Add and verify `blueshieldrobotics.com` in the GitHub account Pages settings using the TXT value generated by GitHub. Keep that verification TXT record.
2. Commit and push the root `CNAME` file after separate approval.
3. Confirm GitHub Pages lists `blueshieldrobotics.com` as its custom domain.
4. Immediately before DNS cutover, remove the custom-domain binding from the Framer project.
5. Replace only the three Framer website records with the target records above.
6. Wait for DNS propagation and confirm both the apex and `www` host resolve to GitHub Pages.
7. Confirm `www` redirects to the apex domain and all site assets return HTTP 200.
8. Enable `Enforce HTTPS` after GitHub provisions the certificate.

## Verification

Run after DNS changes:

```powershell
Resolve-DnsName blueshieldrobotics.com -Type A -DnsOnly
Resolve-DnsName www.blueshieldrobotics.com -Type CNAME -DnsOnly
curl.exe -I https://blueshieldrobotics.com/
curl.exe -I https://www.blueshieldrobotics.com/
```

Expected results:

- The apex returns only the four GitHub Pages IPv4 addresses.
- `www` points to `Henry-811.github.io` and redirects to the apex domain.
- Both hosts have valid HTTPS certificates.
- Existing email DNS records remain unchanged.

## Rollback

If the GitHub Pages cutover fails, restore the two previous Framer A records and the `www` CNAME from the DNS snapshot, then reattach the domain to the Framer project if it was removed. The current DNS TTL is 3600 seconds, so cached responses can remain for about one hour; full propagation can take longer.
